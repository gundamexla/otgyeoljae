이 문서는 현재 코드 검토와 연결 제안이다. 아래의 미구현 항목은 완료된 기능으로 발표하지 않는다.

## 핵심 이야기

**“이번 주말 결혼식에 뭐 입지?”라고 말하면, 옷결재가 가진 옷을 먼저 활용하고 새로 살 것만 골라 금액·환불 조건을 보여준다. 사용자가 승인하면 모의 영수증을 남기고, 구매 후 아쉬웠던 점을 다음 구매 기준에 반영한다.**

현재 저장소의 주인공 표기는 볼티다. 해달 모아를 사용할 경우 이름·화면·발표를 하나로 통일한다. 두 캐릭터 엔진을 동시에 실행할 필요는 없다.

## 90초 시연 — 현재 되는 경로

1. **0–15초:** “이번 주말 결혼식 가는데 뭐 입지” 입력. 데모 캘린더의 11월 8일 결혼식과 샘플 옷장을 근거로 제안한다.
2. **15–35초:** 기존 흰 셔츠 29,000원을 구매에서 제외한다. A안은 블레이저 89,000 + 바지 39,000 + 신발 59,000 + 샘플 배송비 3,000 = **190,000원**. B안은 **83,000원**이다.
3. **35–55초:** 기준 100,000원 이상, 신발 환불 불가라는 이유로 사람 결재를 요청한다. 승인하면 **시뮬레이션 영수증**을 보여준다.
4. **55–75초:** “일주일 후”를 눌러 신발에 “별로”를 선택한다. 신발 카테고리가 자동 처리에서 사람 결재로 바뀐다.
5. **75–90초:** “양말 다 떨어졌어” 입력. 샘플 양말 9,900 + 배송비 3,000 = **12,900원**, 자동 처리된 모의 영수증을 보여준다.

이미지 시착은 별도 사이트에서 직접 사진·의상을 선택하는 장면으로 붙일 수 있다. 현재 옷결재 견적과 시착 결과가 자동으로 연결된 것처럼 설명하면 안 된다. 반복 리허설 전 서버를 재시작하면 데모 예산·영수증·규칙이 초기화된다.

**착장 사이트는 주소만 연결한다고 결과가 옷결재로 넘어오지 않는다.** 확인한 착장 소스는 `/api/try-on` 결과를 현재 브라우저의 이미지 객체로 보관한다. 외부 사이트 POST를 거절하고 로그인과 동의를 요구한다. 외부 호출을 위해 이 검사를 해제하지 않는다.

추천 구현 순서:

1. 옷결재 화면에 **“사진으로 입어보기”** 링크를 넣고 기존 착장 사이트를 연다. 이 단계는 사이트 이동이다.
2. 착장 사이트에 **“이 조합을 옷결재로 보내기”**를 추가한다. 전달 필드는 조합 ID, 의상 ID, 보유/신규 구분, 사용자가 확인한 선택. 공유 결과 이미지는 별도 보관·동의 설계가 필요하다. 임시 `blob:` URL은 다른 브라우저에서 쓸 수 없다.
3. 옷결재 서버가 의상 ID와 판매 상품 ID를 검증하고 새 견적을 계산한다. 이미지 카탈로그의 옷을 실제 판매 상품 또는 사용자 보유 옷으로 자동 간주하지 않는다.
4. 캐릭터가 요청을 보내고 `proposal/approval/receipt`를 표시한다. 견적 ID와 실행 상태는 옷결재 서버 값을 사용한다. 승인 버튼을 누르기 전에 모의 결제임을 표시한다.

하나의 시연에서는 **옷결재 서버를 예산·견적·영수증의 기준**으로 사용한다. 캐릭터의 별도 구매 시나리오와 금융 사이트 잔액을 동시에 진짜 상태처럼 섞지 않는다.

## 먼저 고칠 것

### 시연 흐름을 직접 깨는 부분

1. **반려 후 승인 차단.** 로컬 HTTP 검수에서 반려한 견적을 다시 승인하면 영수증이 생성됐다. `checkout`에서 `pending`만 처리하고, 완료/반려 후 화면 버튼도 함께 비활성화한다. 동일 견적의 이미 완료된 승인은 기존 영수증을 반환한다.
2. **대안 버튼 실제 연결.** `public/index.html`의 `data-a=alt`는 설명만 출력한다. B안으로 새 견적을 만들고 금액·현재 예산을 다시 계산하거나, 구현 전에는 “대안 보기”로 이름을 바꾼다.
3. **API 상태를 정확히 표시.** 현재 “SKT A.X K2 연결됨”은 키 존재 여부다. “키 설정됨”과 “이번 요청 실제 호출 성공”을 구분한다. API 실패 시 고정 샘플 흐름으로 전환되었다고 표시한다.

### 실상품 연결 전에 필요한 부분

- 네이버 검색 결과에 샘플의 `refundable` 값이 그대로 합쳐진다. 실제 판매자의 환불 조건으로 쓰면 안 된다. 확인 전에는 “환불 조건 미확인”으로 처리한다. 배송비 3,000원도 모든 판매처의 실제 배송비가 아니라 고정 샘플이다.
- 화면의 “환불 가능 상품은 7일 안 취소”는 이 코드가 확인한 판매처 조건이 아니다. 검증된 조건만 표시한다.
- 승인 시 최신 예산·규칙·견적 상태를 다시 검사한다. 현재 예산 초과는 사람 결재 사유일 뿐 차단이 아니므로 “생활비를 반드시 보호한다”고 발표할 수 없다. 보호금액을 추가한다면 별도 정책과 강제 조건을 구현한다.
- 키가 없을 때 “안녕”도 결혼식 추천으로 처리됐다. 지원하지 않는 요청에는 가능한 시연 요청을 안내한다.
- 후회 입력 뒤 변경 내용을 보여주고 사용자가 적용·되돌리기를 선택하게 한다. 구매 권한 확대는 자동으로 하지 않는다.

## 로컬 실행과 검수 기록

Node.js 20+가 필요하고 별도 패키지 설치는 없다. 저장소 폴더에서 `npm start` → `http://localhost:4400`.
키 없이도 샘플 시연이 된다. 실제 API 검증 때만 `.env.example`을 `.env`로 복사하고 각자 환경에서 설정한다. `.env`와 사진·대화 원문은 저장소에 넣지 않는다.

2026-11-07 16:26 KST, Node 24.22.1, 별도 로컬 프로세스에서 외부 API 키를 제외하여 검수했다. 실제 API 호출·사진 전송·결제는 수행하지 않았다.

- `node --check server.mjs`: 통과.
- HTTP 확인 7항목: 외부 API 비활성, 홈 응답, A안/대안/셔츠 제외 금액, 모의 승인, 반복 승인 중복 방지, 신발 후회 규칙, 양말 자동 처리 — 통과.
- 발견 사항: 반려 후 재승인이 처리됨. 예산 초과 견적을 승인하면 잔액이 음수가 될 수 있음. 키 없는 일반 인사도 결혼식 추천으로 처리됨.
- 브라우저 버튼의 종합 조작 검수·SKT 실호출·네이버 실검색·착장 결과 전달·캐릭터 연동은 이번 검수 범위가 아니다.
