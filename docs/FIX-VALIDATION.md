# 결재·대안·API 상태 수정

기준: 2026-11-07, 팀의 모아 면접 시나리오가 포함된 `cf17bff`에서 분기.
브랜치: `fix/approval-alternative-api-status`.

## 변경

- 반려·대안으로 교체·처리 중인 견적은 승인할 수 없다(HTTP 409). 이미 결제한 견적은 같은 영수증을 반환한다. 결제 후 반려는 거절하고, 다른 견적에서 같은 요청 식별자를 재사용하면 거절한다.
- 결재 카드의 승인/반려/대안 버튼을 요청 중 함께 잠그고, 완료 후에는 다시 실행하지 못하게 한다. 오류 응답을 결제 성공으로 표시하지 않는다. 팀원이 추가한 모아 버튼에도 비동기 오류 처리를 적용했다.
- `POST /api/alternative {quoteId}`로 서버에 저장된 B안을 다시 계산하고 새 견적을 만든다. 이전 A안은 무효화한다. B안 금액은 샘플 기준 83,000원이며, 대안 선택만으로는 결제하지 않는다. 새로운 카드에서 최종 승인한다.
- 키 설정 여부와 실제 호출 결과를 구분한다. 미호출/호출 성공/대체 제공자 성공/API 실패 후 샘플/키 없는 샘플을 표시한다. HTTP 오류 본문이나 키는 상태·로그에 노출하지 않는다. 오래 걸린 이전 요청이 최신 요청 상태를 덮어쓰지 않는다.

## 검수

`node --test tests/regressions.test.mjs` 또는 `npm test`.

16개 자동 테스트: 반려 후 승인, 반복·동시 승인, 완료 후 반려, 다른 견적의 요청 식별자, A→B 전환, 변경 시 규칙·예산 재계산, 동시 대안 선택, 모아 42,000원 시나리오·피드백, 키 없음/설정/성공, SKT 실패→OpenAI 성공, HTTP 오류·시간 초과·네트워크 오류·잘못된 응답·양쪽 실패·동시 요청 상태, 화면 스크립트 문법.

Chrome에서도 반려 뒤 세 버튼 잠금, B안 83,000원 새 결재 카드, 키 없는 샘플 안내를 확인했다. 팀원의 면접 흐름을 끝까지 조작해 42,000원 모의 영수증·88,000원 가상 잔액·완료 후 승인/반려 버튼 잠금까지 확인했다.

외부 API는 테스트용 응답으로 대체했다. 실제 SKT/OpenAI 연결 성공이나 실결제 검증을 뜻하지 않는다. 테스트는 `.env`가 없는 임시 디렉터리에서 실행되고 종료 후 해당 디렉터리를 정리한다.

이 변경은 세 결함에 한정한다. 기존의 사용자별 상태 분리, 보호 생활비의 결제 시 강제 검증, 네이버 실상품의 환불·배송비 검증, 착장·캐릭터 데이터 연결은 별도 작업이다.
